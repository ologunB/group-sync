Google Sign-In test

Gets a real Google ID token in the browser and posts it to POST /api/v1/auth/social. Dev-only page — it is not served when NODE_ENV=production.

⚠ Before you start

This page's origin must be listed under Authorised JavaScript origins for the OAuth client, or sign-in will stall at accounts.google.com/gsi/transform after you grant permission and never return a token.

Add it at Google Cloud console → APIs & Services → Credentials → your OAuth 2.0 Client ID → Authorised JavaScript origins, then save and give it a minute or two to propagate.

1 · Setup

Must be a Web application client, and this page's origin () must be listed under Authorised JavaScript origins in the Google Cloud console. It also has to match the server's GOOGLE_CLIENT_ID, or the backend will reject the token's audience.

Leave as-is when this page is served by the API itself. Use a full URL to point at another environment.

2 · Sign in with Google

Enter a client ID above and press “Load Google button”.

Fallback: redirect flow

The button above uses Google Identity Services, which exchanges the credential inside a hidden iframe. If third-party cookies are blocked, that stalls at accounts.google.com/gsi/transform after you grant permission and never calls back — the flow looks frozen.

This fallback uses a plain full-page redirect instead: no iframe, no third-party cookies. It needs Authorised redirect URIs to contain (a different console field from JavaScript origins).
